# 系統介面改版 設計

## 目標

把現有前端改成《我獨自升級》的「系統視窗」視覺語言，讓日常操作就有被系統認可的儀式感，並為下一個子專案（獎勵系統：寶箱、圖鑑、金幣、稱號）準備好共用元件。這次只改外觀與前端結構，不新增後端功能。

## 背景與決定

- 風格定為「A2 影之君主」：深色底、漸層細框、宋體視窗標題、霧狀光源、等寬數字。比較用的互動稿見 `https://claude.ai/artifact/MmmS4nEtxhP3YdWq6HFGwb`。
- 三種主題色共用同一套版面：藍光、紫影、翡翠。**預設藍光**；紫影與翡翠在獎勵系統中以金幣解鎖，本次只把三套色票做進樣式，切換介面留到獎勵系統。
- 仍是純 HTML＋JS，無建置步驟；不引入前端框架。
- 前端不計算 EXP、等級、階段，一律用 API 回傳值（既有不變式）。

## 設計

### 1. 設計代號（tokens）

全部定義在 `app.css` 的 `:root`，主題以 `<html data-accent="azure|violet|jade">` 切換，只覆寫色彩代號。

| 代號 | 用途 | 藍光 | 紫影 | 翡翠 |
| --- | --- | --- | --- | --- |
| `--bg` | 頁面底色 | `#050912` | `#07060b` | `#050c0a` |
| `--panel` | 視窗底（半透明） | `rgba(14,26,52,.66)` | `rgba(28,20,44,.66)` | `rgba(14,38,32,.64)` |
| `--panel-solid` | 彈窗底 | `#0b1630` | `#140f22` | `#0b1f1a` |
| `--ink` | 主要文字 | `#e6f1ff` | `#efe9ff` | `#e4fbf3` |
| `--muted` | 次要文字 | `#8aa4c8` | `#a497c4` | `#8fb8aa` |
| `--accent` | 主色 | `#5cb6ff` | `#a585ff` | `#4fdcaa` |
| `--accent-ink` | 主色上的文字 | `#031024` | `#12082a` | `#02150f` |
| `--line`／`--line-soft` | 邊框 | 主色 50%／16% 透明 | 同 | 同 |
| `--edge-hi`／`--edge-lo` | 視窗漸層框兩端 | 依主色 | 依主色 | 依主色 |
| `--glow` | 視窗光暈 | 依主色 | 依主色 | 依主色 |
| `--ok` | 完成 | `#6ee7c8` | `#6ee7c8` | `#c9ec7a` |
| `--warn` | 連勝、警示 | `#f5c56b` | 同 | 同 |
| `--bad` | 錯誤 | `#ff6b7a` | 同 | 同 |

字體（Google Fonts，皆附系統後備字）：
- `--serif`：Noto Serif TC，用於視窗標題、系統訊息、稱號。
- `--sans`：Noto Sans TC，內文。
- `--mono`：IBM Plex Mono，數字與數據，`font-variant-numeric: tabular-nums`。
- `--latin`：Chakra Petch，英文標籤（LEVEL、TODAY、SYSTEM）。

### 2. 共用元件

- **系統視窗 `.win`**：半透明底、1px 漸層框（`border-image`）、光暈、背景模糊；標題 `.win-title` 為宋體、字距 0.3em、兩側漸層細線。每個畫面由數個視窗組成。
- **狀態面板**：等級方塊（LEVEL＋大字等級）、名稱、稱號、圓形階級徽章、EXP 條（主色漸層＋光暈）、數據籤（連勝、達標率；獎勵系統再加金幣與保險卡）。
- **任務列**：名稱、階段標籤（`第 2/10 階`）、屬性與 EXP 小字；完成時名稱淡化加刪除線、勾選框填滿主色並發光。控制項維持 Check／Count／Limit 三種。
- **系統訊息 `sysMessage(lines)`**：取代現有 toast 的成功訊息。頂部浮出的實心視窗，`[ SYSTEM ]` 標頭、宋體內文、多行；3.2 秒自動消失，點擊立即關閉；多則排隊依序顯示。錯誤訊息仍用 toast，配色改用 `--bad`。
- **按鈕**：主要按鈕實心主色、英文大寫字距；次要按鈕細框；危險按鈕 `--bad` 細框。保留既有「再按一次確認」的二段式確認。
- **底部導覽**：中文名＋英文小標（TODAY／STATS／SYS，獎勵系統再加 HUNTER），作用中項目頂端一條發光主色線，格數依項目數平均分配。
- **背景**：`body` 使用主色的兩團徑向漸層加底色，固定不捲動。

### 3. 畫面

導覽維持既有路由，只改視覺，並把第三格預留給獎勵系統的「檔案」：

| 路由 | 導覽 | 內容 |
| --- | --- | --- |
| `#today` | 今日 TODAY | 狀態面板、每日任務視窗（含達成率與門檻）、今日反思視窗 |
| `#progress` | 進度 STATS | 66 天日曆視窗、五維屬性視窗、最近 7 天視窗 |
| `#settings` | 設定 SYS | 困難模式、目標、任務管理、66 天計畫、帳號 |
| `#onboarding` | 隱藏導覽 | 三步引導，視窗化、步驟以 `STEP 1 / 3` 標示 |
| `#login`／`#register` | 隱藏導覽 | 置中單一視窗，標題「玩家登錄」，系統風格歡迎語 |

本次導覽為三格（今日、進度、設定）；獎勵系統上線時插入第三格「檔案 HUNTER」成為四格。

- Header 改為今日頁頂部的狀態面板；其他頁頂部顯示精簡版（等級、EXP 條、階級）。
- 66 天日曆的格子改為小方塊：達標＝主色實心加光暈、未達標＝細框、今日＝主色框閃爍一次、未來＝極淡框；點格子顯示日期（取代只能 hover 的 `title`）。
- 系統訊息的時機：完成任務（「每日任務『閱讀』完成。獲得 20 EXP、INT +1。」）、今日達標、升級（後端回應的等級高於前一次）、目標升階（今日回應的階段高於前一次快取）。等級與階段比較用前端記住的上一次 `/me`、`/today` 值，不改 API。

### 4. 實作邊界

- 只動 `wwwroot/index.html`、`app.css`、`app.js`；`app.js` 若超過約 700 行，拆出 `ui.js`（元件與系統訊息）與 `app.js`（路由與畫面），用 `<script>` 依序載入。
- 不改任何 API 與後端；既有整合測試不受影響。
- 觸控友善：可點擊元素至少 40×40px；`touch-action: manipulation`；safe-area 內距補齊 Header、導覽與系統訊息。
- 尊重 `prefers-reduced-motion`：關閉光暈呼吸、閃爍與訊息位移動畫。

### 5. 驗收

- 三個主題（以 `data-accent` 手動切換驗證）在今日、進度、設定、引導、登入五個畫面都正確著色，無寫死色碼。
- 勾選任務、達標、升級、目標升階各會出現一則系統訊息；錯誤仍顯示紅色 toast。
- 375px 寬手機上無橫向捲動；日曆可點格看日期。
- 既有 207 個測試全綠。

## 這次不做

主題切換介面與解鎖、檔案頁、寶箱、金幣、卡片、稱號組合（皆屬獎勵系統）；PWA 與離線；頁面轉場動畫。
