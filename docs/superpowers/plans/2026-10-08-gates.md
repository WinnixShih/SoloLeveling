# 傳送門挑戰 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以 E～S 六級「傳送門挑戰」取代固定的 66 天計畫：玩家逐級解鎖、自選開門，門期間依每日達標判定通關或失敗，通關發依等級的寶箱並在首次通關解鎖成就。

**Architecture:** Domain 新增等級表 `Gates.All`、實體 `Gate` 與純規則 `GateRules`（第幾天、最後一天、通關／失敗判定）；`Rewards.Evaluate` 改收「本次通關的等級」並發 `ChestSource.Gate` 寶箱，成就統計改為各等級通關次數。Api 新增 `GateTracker`（查進行中的門、一次 COUNT 算已漏天數、判定並寫入結果、批次查通關次數），由 `RewardApplier` 在目標完成判定旁呼叫；`GateService`／`GatesController` 提供 `GET /gates`、`POST /gates`、`POST /gates/active/abandon`。一支 migration 刪 `Programs`、建 `Gates`。前端進度頁改為傳送門視窗、今日狀態面板加傳送門籤、設定頁移除 66 天區塊。

**Tech Stack:** .NET 10、EF Core 10＋Npgsql（PostgreSQL 16）、xUnit＋FluentAssertions＋Testcontainers、純 HTML＋JS 前端（`ui.js`／`app.js`／`hunter.js`／`app.css`）

**Spec:** `docs/superpowers/specs/2026-10-08-gates-design.md`（使用者已核可）；專案規則 `CLAUDE.md`、`docs/ARCHITECTURE.md`、`docs/SPEC.md`；沿用模式參考 `docs/superpowers/specs/2026-10-01-rewards-cards-titles-design.md`、`docs/superpowers/plans/2026-10-01-rewards-cards-titles.md`。

## Global Constraints

規格原文的數值與規則（逐字照抄，不得更動）：

- 門分 E、D、C、B、A、S 六級，與玩家階級同一套名稱。逐級解鎖：通關某一級的門，才能挑戰上一級。
- 等級表：E 5 天、可漏 1、E 箱 ×1、成就「破繭」（前綴「破繭的」）；D 10 天、可漏 2、C 箱 ×1、成就「D 級獵人」（後綴「D 級獵人」）；C 20 天、可漏 3、A 箱 ×1、成就「C 級獵人」（後綴「C 級獵人」）；B 35 天、可漏 5、A 箱 ×2、成就「B 級獵人」（後綴「B 級獵人」）；A 60 天、可漏 8、S 箱 ×1、A 箱 ×1、成就「A 級獵人」（後綴「A 級獵人」）；S 100 天、可漏 10、S 箱 ×3、成就「S 級獵人」（後綴「S 級獵人」）。
- 重複通關同一級的門只拿寶箱，成就（稱號字塊）只在首次通關時解鎖一次。「破繭」改為「通關第一道傳送門」；成就總數由 12 個變為 17 個。
- 開門當天為第 1 天。同時只能有一道進行中的門。E 級門一開始就能選；其餘等級需先通關低一級的門至少一次。
- 漏一天：門期間內、已結算且未達標（`DailyLog.IsCleared = false`）的日子。被保險卡保住的日子仍未達標，所以照樣算漏；保險卡只讓連勝不中斷。
- 失敗：漏的天數超過上限時，這道門立即判定失敗。失敗沒有額外懲罰，可以馬上重新挑戰同一級。
- 通關：今天是最後一天、今天已達標，且漏的天數沒有超過上限：當天立即通關；或最後一天結算後，漏的天數沒有超過上限。
- 通關或失敗一經寫入就不再改變；最後一天當天通關後，即使撤銷任務使當天變成未達標，也不撤回通關。
- 放棄：玩家可以主動放棄進行中的門，放棄視同失敗。通關、失敗或放棄後，不會自動開下一道門。
- 判定放在 `RewardApplier`，與目標完成判定同一個位置；漏的天數由 `DailyLogs` 在門期間內批次查詢計算，不另外存欄位；通關寶箱來源為新的 `ChestSource.Gate`。
- `Gates` 表：`Id`、`UserId`、`Rank`（E～S，字串，`HasMaxLength(16)`）、`StartDate`（date）、`LengthDays`、`AllowedMisses`、`Status`（`Active`／`Cleared`／`Failed`／`Abandoned`，字串）、`EndedAt`（Unix 毫秒，nullable）、`CreatedAt`；每位玩家同時只能有一筆 `Status = Active`（partial unique index）。一支 migration：刪除 `Programs` 表、建立 `Gates` 表；註冊時不再自動建立 66 天週期。
- API：`GET /gates`（200）、`POST /gates { rank }`（200 進行中的門與 `rewards`；未解鎖 400 `GateLocked`，已有進行中的門 409 `GateInProgress`）、`POST /gates/active/abandon`（200 `{ rewards }`；沒有進行中的門 404 `NoActiveGate`）。`/me` 的 `program` 改為 `activeGate`（沒有時為 null）。`RewardsDto` 新增 `gateCleared`、`gateFailed`（等級或 null）。`POST /program/restart` 移除。
- 前端：進度頁頂部「傳送門」視窗；今日頁狀態面板傳送門標籤（例「C 級門 8/20・漏 1/3」，沒進門不顯示）；設定頁移除「66 天計畫」區塊；系統訊息開門、通關（含獎勵寶箱）、失敗各一則，排在獎勵訊息的寶箱之前；手機 375px 寬無橫向捲動。

專案規則（`CLAUDE.md`／全域規則）：

- 依賴方向 Api → Infrastructure → Domain；Domain 不引用框架。
- 建置開 `TreatWarningsAsErrors`、`EnforceCodeStyleInBuild`；src 專案 public 型別與成員必須有 XML 註解，方法要完整 `<param>`／`<returns>`／`<exception>`，不用 `<inheritdoc />`。控制流一律加大括號。
- `catch` 只接已知例外；本計畫沒有新增任何 `catch`。前端只 catch `UI.ApiError`（沿用 `showError`／`UI.confirmButton`）。
- Player.Xp 變動必有 XpEvent；Player.Coins 變動一律經 `Wallet.Change`／`Wallet.Spend` 並寫 CoinEvent（成就金幣沿用 `RewardApplier` 既有寫法）。

## Rulings（規格未明定、本計畫的決定）

1. **成就鍵改為 `gate-e`～`gate-s`**（破繭不再叫 `program-complete`）。migration 把既有的 `program-complete` 成就列與稱號前綴改成 `gate-e`、`ProgramCompleted` 寶箱來源改成 `Gate`；否則讀取舊寶箱時字串轉 enum 會失敗、已選的稱號字塊會查不到。
2. **`GET /gates` 也走 `ApplyOnReadAsync` 並回傳 `rewards`**：它要回正確的進行中的門，不能依賴前端先打 `/me` 才補判定（那是跨元件的時序耦合）；回應帶 `rewards`，因此不會吃掉待公告的保險卡事件。
3. **開門與放棄先判定進行中的門**（`GateTracker.ResolveAsync`），再檢查 409／404；結果傳給 `ApplyAsync(resolvedGate:)`，同一請求不重複判定。前一道門剛在結算後通關時，`POST /gates` 會在同一個回應帶 `gateCleared` 並開好下一級；放棄時若門已在判定中結束，回 200 並帶 `gateCleared`／`gateFailed`，不改成放棄。
4. **放棄不填 `gateFailed`**：`gateFailed` 只表示「漏的天數超過上限」；放棄寫 `Status = Abandoned`，系統訊息由前端在放棄成功後自行顯示。
5. **`rank` 驗證**：`OpenGateRequest.Rank` 為 `GateRank?`；缺漏或未定義的數值（例如 `9`）回 400 `InvalidGateRank`；非 enum 名稱的字串由模型繫結回 400 `ValidationFailed`（既有格式）。檢查順序：`InvalidGateRank` → `GateInProgress`（409）→ `GateLocked`（400）。
6. **`dayNumber` 夾在 1～`LengthDays`**：使用者改時區可能讓今日早於開門日，或在同一天讀取時門已過最後一天但尚未被判定，顯示值不會出現 0 或超過總天數。
7. **`RewardApplier.ApplyAsync` 移除 `completedPrograms` 參數**，簽章改為 `ApplyAsync(TodayContext context, CancellationToken ct, int alreadyCompletedGoals = 0, GateResolution? resolvedGate = null)`；判定順序：目標完成 → 傳送門（判定有變就先存檔，統計查詢才看得到本次通關）→ 統計 → `Rewards.Evaluate`。
8. **`ChestSource.Gate = 8`**，不重用 `ProgramCompleted` 的 6（DB 存字串，數值只用於程式內；不重用避免閱讀時混淆）。
9. **前端訊息**：通關訊息列出該次傳送門寶箱並附「前往『檔案』開啟」，寶箱訊息只列其他來源的寶箱；開門訊息在開門回應後立即顯示，再重跑路由顯示獎勵。
10. **今日頁傳送門籤放在 `UI.statusPanel` 完整版**（今日頁與檔案頁都顯示完整版面板），由 `me.activeGate` 驅動。
11. **未解鎖的門顯示條件來自 API**：`GateTierDto.RequiredRank`，前端不自己推算上一級。
12. **開門單擊即送出、放棄二段式確認**（規格只要求放棄二段式）。

## Review Focus

1. **結算後第一個請求就是開下一級門**：E 門最後一天已結算、尚未被任何請求判定時直接 `POST /gates { rank: "D" }`，不得回 409，要先補判定通關、發 E 箱與破繭，再開 D 門。→ Task 3 `OpenGate_前一道門最後一天已結算_同一請求先補通關再開下一級`。
2. **最後一天達標後撤銷**：通關當下發箱；撤銷任務後不撤回通關、不收回寶箱，隔天讀取也不重發。→ Task 2 `最後一天達標當下通關_撤銷後仍維持通關且不重發`。
3. **保險卡保住的日子**：連勝延續、保險卡被消耗，但門的已漏天數仍 +1。→ Task 2 `保險卡保住的日子_連勝不中斷但仍算漏一天`。
4. **無效或缺漏的 rank**（數字 `9`、空物件、亂寫字串）：一律 400，不得 500，也不得開出門。→ Task 3 `OpenGate_等級無效或缺漏_回400且不開門`。
5. **跨時區的開門日**：台北使用者在 UTC 17:00（台北隔天 01:00）開門，開門日要是台北的日期。→ Task 3 `OpenGate_台北使用者跨日_開門日為使用者時區的今日`。

```csharp
/// <summary>
/// 一個等級的傳送門定義。
/// </summary>
/// <param name="Rank">等級。</param>
/// <param name="LengthDays">天數；開門當天為第 1 天。</param>
/// <param name="AllowedMisses">最多可漏天數；超過即失敗。</param>

/// <param name="AchievementKey">首次通關解鎖的成就鍵（見 <see cref="Achievements"/>）。</param>
/// <param name="RequiredRank">需先通關至少一次的等級；E 級為 null。</param>
public sealed record GateDefinition(
    GateRank Rank,
    int LengthDays,
    int AllowedMisses,
    IReadOnlyList<Rarity> Chests,
    string AchievementKey,
    GateRank? RequiredRank);

/// <summary>
/// 傳送門等級表；順序即顯示順序，也是解鎖順序。S 級寶箱只出現在 A、S 級門。
/// </summary>
public static class Gates
{
    /// <summary>六級門。</summary>
    public static IReadOnlyList<GateDefinition> All { get; } =
    [
        new(GateRank.E, 5, 1, [Rarity.E], "gate-e", null),
        new(GateRank.D, 10, 2, [Rarity.C], "gate-d", GateRank.E),
        new(GateRank.C, 20, 3, [Rarity.A], "gate-c", GateRank.D),
        new(GateRank.B, 35, 5, [Rarity.A, Rarity.A], "gate-b", GateRank.C),
        new(GateRank.A, 60, 8, [Rarity.S, Rarity.A], "gate-a", GateRank.B),
        new(GateRank.S, 100, 10, [Rarity.S, Rarity.S, Rarity.S], "gate-s", GateRank.A),
    ];

    private static readonly Dictionary<GateRank, GateDefinition> Index = All.ToDictionary(g => g.Rank);

    /// <summary>
    /// 依等級取定義。
    /// </summary>
    /// <param name="rank">等級。</param>
    /// <returns>定義。</returns>
    /// <exception cref="ArgumentOutOfRangeException">未定義的等級（呼叫端應先驗證輸入）。</exception>
    public static GateDefinition Of(GateRank rank)
    {
        if (!Index.TryGetValue(rank, out var definition))
        {
            throw new ArgumentOutOfRangeException(nameof(rank), rank, "未定義的傳送門等級");
        }

        return definition;
    }

    /// <summary>
    /// 是否已解鎖：E 級永遠可開，其餘需低一級通關至少一次。
    /// </summary>
    /// <param name="rank">要開的等級。</param>
    /// <param name="clearCounts">各等級的通關次數；沒有通關的等級可不在字典內。</param>
    /// <returns>已解鎖為 true。</returns>
    public static bool IsUnlocked(GateRank rank, IReadOnlyDictionary<GateRank, int> clearCounts)
    {
        return Of(rank).RequiredRank is not { } required || clearCounts.GetValueOrDefault(required) > 0;
    }
```

```csharp
using SoloLeveling.Domain.Entities;

namespace SoloLeveling.Domain.Rules;

/// <summary>
/// 傳送門的純規則：第幾天、最後一天、通關與失敗判定。已漏天數由呼叫端從已結算且未達標的 DailyLog 算好傳入。
/// </summary>
public static class GateRules
{
    /// <summary>
    /// 門的最後一天。
    /// </summary>
    /// <param name="gate">門。</param>
    /// <returns>開門日 + 天數 − 1。</returns>
    public static DateOnly LastDay(Gate gate)
    {
        return gate.StartDate.AddDays(gate.LengthDays - 1);
    }

    /// <summary>
    /// 顯示用的第幾天：開門日為 1，夾在 1 到天數之間（改時區可能讓今日早於開門日）。
    /// </summary>
    /// <param name="gate">門。</param>
    /// <param name="today">使用者時區的今日。</param>
    /// <returns>1 到 <see cref="Gate.LengthDays"/>。</returns>
    public static int DayNumber(Gate gate, DateOnly today)
    {
        return Math.Clamp(today.DayNumber - gate.StartDate.DayNumber + 1, 1, gate.LengthDays);
    }

    /// <summary>
    /// 判定進行中的門：已漏天數超過上限即失敗；今天是最後一天且已達標、或今天已過最後一天，即通關；否則進行中。
    /// </summary>
    /// <param name="gate">進行中的門。</param>
    /// <param name="today">使用者時區的今日。</param>
    /// <param name="misses">門期間內已結算且未達標的天數（保險卡保住的日子也算）。</param>
    /// <param name="todayCleared">今日目前是否達標。</param>
    /// <returns>判定結果。</returns>
    public static GateVerdict Judge(Gate gate, DateOnly today, int misses, bool todayCleared)
    {
        if (misses > gate.AllowedMisses)
        {
            return GateVerdict.Failed;
        }

        var lastDay = LastDay(gate);
        if (today > lastDay || (today == lastDay && todayCleared))
        {
            return GateVerdict.Cleared;
        }

        return GateVerdict.InProgress;
    }
}
```

```csharp
using Microsoft.EntityFrameworkCore;
using SoloLeveling.Domain;
using SoloLeveling.Domain.Entities;
using SoloLeveling.Domain.Rules;
using SoloLeveling.Infrastructure;

namespace SoloLeveling.Api.Services;

/// <summary>
/// 進行中的門與目前已漏的天數。
/// </summary>
/// <param name="Gate">門（已被 DbContext 追蹤）。</param>
/// <param name="Misses">門期間內已結算且未達標的天數。</param>
public sealed record ActiveGateState(Gate Gate, int Misses);

/// <summary>
/// 一次傳送門判定的結果。
/// </summary>
/// <param name="Cleared">本次通關的等級；沒有為 null。</param>
/// <param name="Failed">本次失敗的等級；沒有為 null。</param>
/// <param name="Active">判定後仍在進行中的門；沒有為 null。</param>
public sealed record GateResolution(GateRank? Cleared, GateRank? Failed, ActiveGateState? Active)
{
    /// <summary>沒有進行中的門，本次也沒有門結束。</summary>
    public static GateResolution None { get; } = new(null, null, null);
}

/// <summary>
/// 傳送門的查詢與判定。已漏天數每次由 DailyLogs 一次 COUNT 算出，不存欄位；通關或失敗一經寫入就不再判定。
/// 必須在呼叫端開啟的交易內、<see cref="TodayContextLoader.LoadAsync"/> 之後使用。
/// </summary>
/// <param name="db">DbContext。</param>
/// <param name="clock">時間來源。</param>
public class GateTracker(AppDbContext db, TimeProvider clock)
{
    /// <summary>
    /// 載入進行中的門與已漏天數（兩次查詢，不隨天數增加）。
    /// </summary>
    /// <param name="userId">使用者 ID。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>進行中的門；沒有為 null。</returns>
    public async Task<ActiveGateState?> LoadActiveAsync(Guid userId, CancellationToken ct)
    {
        var gate = await db.Gates.SingleOrDefaultAsync(g => g.UserId == userId && g.Status == GateStatus.Active, ct);
        if (gate is null)
        {
            return null;
        }

        var startDate = gate.StartDate;
        var lastDay = GateRules.LastDay(gate);
        var misses = await db.DailyLogs.CountAsync(
            l => l.UserId == userId && l.Date >= startDate && l.Date <= lastDay && l.IsSettled && !l.IsCleared,
            ct);
        return new ActiveGateState(gate, misses);
    }

    /// <summary>
    /// 判定進行中的門；通關或失敗時寫入狀態與 <see cref="Gate.EndedAt"/> 並立即 SaveChanges，讓之後的統計查詢看得到本次通關。
    /// </summary>
    /// <param name="context">今日內容（今日達標狀態已反映本次修改）。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>判定結果；沒有進行中的門回 <see cref="GateResolution.None"/>。</returns>
    public async Task<GateResolution> ResolveAsync(TodayContext context, CancellationToken ct)
    {
        var active = await LoadActiveAsync(context.User.Id, ct);
        if (active is null)
        {
            return GateResolution.None;
        }

        var verdict = GateRules.Judge(active.Gate, context.Today, active.Misses, context.TodayLog.IsCleared);
        if (verdict == GateVerdict.InProgress)
        {
            return new GateResolution(null, null, active);
        }

        active.Gate.Status = verdict == GateVerdict.Cleared ? GateStatus.Cleared : GateStatus.Failed;
        active.Gate.EndedAt = clock.GetUtcNow();
        await db.SaveChangesAsync(ct);
        return verdict == GateVerdict.Cleared
            ? new GateResolution(active.Gate.Rank, null, null)
            : new GateResolution(null, active.Gate.Rank, null);
    }

    /// <summary>
    /// 各等級的通關次數（一次查詢）。
    /// </summary>
    /// <param name="userId">使用者 ID。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>等級對通關次數；沒有通關的等級不在字典內。</returns>
    public async Task<Dictionary<GateRank, int>> LoadClearCountsAsync(Guid userId, CancellationToken ct)
    {
        return await db.Gates
            .Where(g => g.UserId == userId && g.Status == GateStatus.Cleared)
            .GroupBy(g => g.Rank)
            .Select(g => new { Rank = g.Key, Count = g.Count() })
            .ToDictionaryAsync(x => x.Rank, x => x.Count, ct);
    }
}
```

```csharp
    /// 判定並持久化本次請求的獎勵；方法結尾會再 SaveChanges 一次。
    /// </summary>
    /// <param name="context">今日內容（已反映本次修改並存檔）。</param>
    /// <param name="ct">取消權杖。</param>
    /// <param name="alreadyCompletedGoals">呼叫端先以 <see cref="CompleteFinishedGoalsAsync"/> 標記完成的目標數（封存會讓目標不再被判定，要先標記）。</param>
    /// <param name="resolvedGate">呼叫端已用 <see cref="GateTracker.ResolveAsync"/> 判定過傳送門時傳入（開門、放棄要先判定才知道能否進行）；null 表示由本方法判定。</param>
    /// <returns>本次獎勵，放進回應的 <c>rewards</c> 欄位。</returns>
    public async Task<RewardsDto> ApplyAsync(TodayContext context, CancellationToken ct, int alreadyCompletedGoals = 0, GateResolution? resolvedGate = null)
    {
        var now = clock.GetUtcNow();
        var player = context.Player;
        var completedGoals = alreadyCompletedGoals + await CompleteFinishedGoalsAsync(context, ct);
        // 傳送門判定有結果時會先存檔，下面的統計才算得到本次通關（首次通關成就）
        var gate = resolvedGate ?? await gateTracker.ResolveAsync(context, ct);
        player.RewardsEvaluatedDate = context.Today;
        var state = await statsLoader.LoadAsync(player, context.Today, ct);
        var outcome = Rewards.Evaluate(new RewardInput(
            context.Before,
            player,
            context.TodayLog,
            state.UnlockedKeys,
            state.Stats,
            completedGoals,
            gate.Cleared));

        player.PeakLevel = outcome.NewPeakLevel;
        player.ShieldCount += outcome.ShieldsGained;
        context.TodayLog.ClearCoinsGranted = outcome.ClearCoinsGranted;

        var chests = outcome.Chests
            .Select(c => new RewardChest { Id = Guid.NewGuid(), UserId = player.UserId, Rarity = c.Rarity, Source = c.Source, CreatedAt = now })
            .ToList();
        db.RewardChests.AddRange(chests);
        db.Achievements.AddRange(outcome.NewAchievements.Select(a => new Achievement { UserId = player.UserId, Key = a.Key, UnlockedAt = now }));
        foreach (var grant in outcome.Coins)
        {
            Guid? refId = grant.Source is CoinSource.DailyClear or CoinSource.DailyClearUndo ? context.TodayLog.Id : null;
            db.CoinEvents.Add(Wallet.Change(player, grant.Amount, grant.Source, refId, now));
        }

        var shieldEvents = await db.RewardEvents
            .Where(e => e.UserId == player.UserId && e.Kind == RewardEventKind.ShieldUsed && e.AnnouncedAt == null)
            .OrderBy(e => e.Date)
            .ToListAsync(ct);
        foreach (var shieldEvent in shieldEvents)
        {
            shieldEvent.AnnouncedAt = now;
        }

        await db.SaveChangesAsync(ct);
        return new RewardsDto(
            outcome.LevelsGained,
            outcome.RankUps.ToList(),
            chests.Select(c => c.ToDto()).ToList(),
            outcome.NewAchievements.Select(a => a.ToUnlockedDto()).ToList(),
            outcome.Coins.Sum(c => c.Amount),
            outcome.ShieldsGained,
            shieldEvents.Select(e => e.Date).ToList(),
            player.ShieldCount,
            gate.Cleared,
            gate.Failed);
    }

    /// <summary>
    /// 讀取端點（GET /today、GET /me、GET /gates）用：本次請求新結算了日子、有待公告的保險卡事件、或今天還沒完整判定過時，等同 <see cref="ApplyAsync"/>；
    /// 其餘情況略過統計查詢與獎勵判定，只回傳空獎勵。因此每位使用者每天至少完整判定一次，排程在請求之外結算造成的獎勵與傳送門結果最晚在當天第一次讀取補上。
    /// </summary>
    /// <param name="context">今日內容。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>本次獎勵，放進回應的 <c>rewards</c> 欄位。</returns>
    public async Task<RewardsDto> ApplyOnReadAsync(TodayContext context, CancellationToken ct)
    {
        if (context.SettledDays > 0
            || context.Player.RewardsEvaluatedDate != context.Today
            || await db.RewardEvents.AnyAsync(e => e.UserId == context.User.Id && e.Kind == RewardEventKind.ShieldUsed && e.AnnouncedAt == null, ct))
        {
            return await ApplyAsync(context, ct);
        }

        return new RewardsDto(0, [], [], [], 0, 0, [], context.Player.ShieldCount, null, null);
    }
```

```csharp
using SoloLeveling.Api.Contracts;
using SoloLeveling.Api.Errors;
using SoloLeveling.Domain;
using SoloLeveling.Domain.Entities;
using SoloLeveling.Infrastructure;

namespace SoloLeveling.Api.Services;

/// <summary>
/// 傳送門：列出等級、開門、放棄。開門與放棄前都先判定進行中的門，結算後剛通關或失敗的門不會擋住開新門，判定結果也會在同一個回應公告。
/// </summary>
/// <param name="db">DbContext。</param>
/// <param name="loader">今日內容載入（含結算與列鎖）。</param>
/// <param name="rewardApplier">獎勵判定與持久化。</param>
/// <param name="gateTracker">傳送門查詢與判定。</param>
/// <param name="clock">時間來源。</param>
public class GateService(AppDbContext db, TodayContextLoader loader, RewardApplier rewardApplier, GateTracker gateTracker, TimeProvider clock)
{
    /// <summary>
    /// GET /gates：先結算並依讀取規則補判定，再列出六級門與進行中的門。
    /// </summary>
    /// <param name="userId">使用者 ID。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>等級表、進行中的門與本次獎勵。</returns>
    public async Task<GatesResponse> ListAsync(Guid userId, CancellationToken ct)
    {
        await using var tx = await db.Database.BeginTransactionAsync(ct);
        var context = await loader.LoadAsync(userId, ct);
        var rewards = await rewardApplier.ApplyOnReadAsync(context, ct);
        var active = await gateTracker.LoadActiveAsync(userId, ct);
        var clearCounts = await gateTracker.LoadClearCountsAsync(userId, ct);
        await tx.CommitAsync(ct);
        return new GatesResponse(
            Gates.All.Select(g => g.ToDto(clearCounts)).ToList(),
            active?.Gate.ToDto(context.Today, active.Misses),
            rewards);
    }

    /// <summary>
    /// POST /gates：從今日開一道已解鎖的門。
    /// </summary>
    /// <param name="userId">使用者 ID。</param>
    /// <param name="rank">等級。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>新開的門（含本次獎勵）。</returns>
    /// <exception cref="ApiErrorException">等級缺漏或未定義（400 <c>InvalidGateRank</c>）、已有進行中的門（409 <c>GateInProgress</c>）、未解鎖（400 <c>GateLocked</c>）。</exception>
    public async Task<ActiveGateDto> OpenAsync(Guid userId, GateRank? rank, CancellationToken ct)
    {
        if (rank is not { } value || !Enum.IsDefined(value))
        {
            throw ApiErrorException.BadRequest("InvalidGateRank", "傳送門等級需為 E、D、C、B、A、S 其中之一");
        }

        await using var tx = await db.Database.BeginTransactionAsync(ct);
        var context = await loader.LoadAsync(userId, ct);
        var resolution = await gateTracker.ResolveAsync(context, ct);
        if (resolution.Active is not null)
        {
            throw ApiErrorException.Conflict("GateInProgress", "已有進行中的傳送門");
        }

        var definition = Gates.Of(value);
        var clearCounts = await gateTracker.LoadClearCountsAsync(userId, ct);
        if (!Gates.IsUnlocked(value, clearCounts))
        {
            throw ApiErrorException.BadRequest("GateLocked", $"需先通關 {definition.RequiredRank} 級傳送門");
        }

        var gate = new Gate
        {
            Id = Guid.NewGuid(),
            UserId = userId,
            Rank = value,
            StartDate = context.Today,
            LengthDays = definition.LengthDays,
            AllowedMisses = definition.AllowedMisses,
            Status = GateStatus.Active,
            CreatedAt = clock.GetUtcNow(),
        };
        db.Gates.Add(gate);
        await db.SaveChangesAsync(ct);
        var rewards = await rewardApplier.ApplyAsync(context, ct, resolvedGate: resolution);
        await tx.CommitAsync(ct);
        return gate.ToDto(context.Today, 0) with { Rewards = rewards };
    }

    /// <summary>
    /// POST /gates/active/abandon：放棄進行中的門（沒有懲罰，可立刻重開）。門若已在判定中通關或失敗，以判定結果為準、不改成放棄。
    /// </summary>
    /// <param name="userId">使用者 ID。</param>
    /// <param name="ct">取消權杖。</param>
    /// <returns>本次獎勵。</returns>
    /// <exception cref="ApiErrorException">沒有進行中的門（404 <c>NoActiveGate</c>）。</exception>
    public async Task<RewardsEnvelope> AbandonAsync(Guid userId, CancellationToken ct)
    {
        await using var tx = await db.Database.BeginTransactionAsync(ct);
        var context = await loader.LoadAsync(userId, ct);
        var resolution = await gateTracker.ResolveAsync(context, ct);
        if (resolution.Active is null && resolution.Cleared is null && resolution.Failed is null)
        {
            throw ApiErrorException.NotFound("NoActiveGate", "目前沒有進行中的傳送門");
        }

        if (resolution.Active is { } active)
        {
            active.Gate.Status = GateStatus.Abandoned;
            active.Gate.EndedAt = clock.GetUtcNow();
            await db.SaveChangesAsync(ct);
        }

        var rewards = await rewardApplier.ApplyAsync(context, ct, resolvedGate: resolution with { Active = null });
        await tx.CommitAsync(ct);
        return new RewardsEnvelope(rewards);
    }
}
```
